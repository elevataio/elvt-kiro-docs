# API Design Standards

## REST API Conventions

- Base URL format: `https://api.{domain}/{version}/{resource}`
- Version prefix: `/v1/` (included in path, not headers)
- Resource names: plural nouns, lowercase, kebab-case for multi-word (e.g., `/v1/orders`, `/v1/order-items`)
- Use HTTP methods correctly:

| Method | Purpose | Idempotent | Response Code |
|--------|---------|-----------|---------------|
| GET | Retrieve resource(s) | Yes | 200 |
| POST | Create new resource | No | 201 |
| PUT | Replace entire resource | Yes | 200 |
| PATCH | Partial update | No | 200 |
| DELETE | Remove resource | Yes | 204 |

## Request Format

- Content-Type: `application/json`
- Authentication: Bearer token in `Authorization` header
- Correlation ID: `x-correlation-id` header (generated by client or API Gateway)
- Pagination: use `?page=1&page_size=20` query parameters

## Response Format

All responses follow a consistent envelope structure:

### Success Response

```json
{
  "data": {
    "id": "ord-123456",
    "type": "order",
    "attributes": {
      "status": "pending",
      "total": 99.99,
      "created_at": "2025-01-15T10:30:00Z"
    }
  },
  "meta": {
    "correlation_id": "abc-def-123",
    "timestamp": "2025-01-15T10:30:00Z"
  }
}
```

### List Response (with pagination)

```json
{
  "data": [
    {"id": "ord-123", "type": "order", "attributes": {...}},
    {"id": "ord-124", "type": "order", "attributes": {...}}
  ],
  "meta": {
    "total_count": 150,
    "page": 1,
    "page_size": 20,
    "correlation_id": "abc-def-123"
  }
}
```

### Error Response

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The request body is invalid",
    "details": [
      {"field": "email", "message": "Must be a valid email address"},
      {"field": "quantity", "message": "Must be greater than 0"}
    ]
  },
  "meta": {
    "correlation_id": "abc-def-123",
    "timestamp": "2025-01-15T10:30:00Z"
  }
}
```

## Error Codes

Use standard HTTP status codes with custom error codes for client differentiation:

| HTTP Status | Error Code | Meaning |
|------------|-----------|---------|
| 400 | VALIDATION_ERROR | Request body/params invalid |
| 401 | UNAUTHORIZED | Missing or invalid token |
| 403 | FORBIDDEN | Valid token, insufficient permissions |
| 404 | NOT_FOUND | Resource does not exist |
| 409 | CONFLICT | Resource state conflict (duplicate, etc.) |
| 429 | RATE_LIMITED | Too many requests |
| 500 | INTERNAL_ERROR | Unexpected server error |

## Input Validation

- Validate all input at the API Gateway level (request validators) AND in Lambda
- Reject unexpected fields (strict schema)
- Sanitize string inputs (trim whitespace, limit length)
- Use Pydantic models for request/response validation in Python

```python
from pydantic import BaseModel, Field, EmailStr

class CreateOrderRequest(BaseModel):
    customer_email: EmailStr
    items: list[OrderItem] = Field(min_length=1, max_length=50)
    shipping_address: Address

    class Config:
        extra = "forbid"  # Reject unknown fields
```

## Rate Limiting

- Default: 1000 requests/second per API key
- Burst: 2000 requests
- Per-customer: 100 requests/second
- Configure via API Gateway usage plans and throttling
